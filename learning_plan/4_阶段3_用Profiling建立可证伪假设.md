# 阶段 3 指导：用 Profiling 建立可证伪的优化假设

> 对应总计划的阶段 3  
> 建议用时：4～6 天  
> 本阶段原则：先看证据，再改代码；每个假设都必须允许被实验否定。

## 一、学习目标

完成本阶段后，你应能：

1. 正确阅读 `PipeUtilization` 和 `ResourceConflictRatio`；
2. 区分活跃时间、等待比例、任务总时间和指令数量；
3. 将硬件指标映射回具体代码；
4. 写出带预期指标变化的实验假设；
5. 避免把累计统计误认为内部 Timeline。

## 三、正确理解管线指标

### 1. active 不是独立串行阶段

Cube、Scalar、MTE1、MTE2、MTE3 可以并行或交叠。它们的 active 时间不能相加得到 kernel 总时间。

例如：

```text
74.628 + 905.685 + 223.585 + 2593.450 + 27.847
= 3825.195 μs
```

已经明显大于 `aic_time=2615.584 μs`，这正说明各管线口径存在重叠，而不是数据错误。

### 2. active 低不等于没有工作

Cube active 只有约 2.85%，但 `ArithmeticUtilization.csv` 同时记录：

```text
aic_cube_total_instr_number = 11312
```

代码也能静态推出 11,312 次 Mmad。低活跃表示 Cube 不是持续繁忙，不表示 Mmad 没执行。

### 3. wait 不能简单与 active 拼成 100%

active ratio 和 wait ratio 来自不同事件及统计语义，不应使用：

```text
idle = 1 - active - wait
```

推导一个未经文档确认的“空闲比例”。应把 wait 当作依赖和资源冲突线索，再结合代码和实验分析。

### 4. MTE2 active 接近 100% 是线索，不是完整证明

它提示 MTE2 非常繁忙，但还需要回答：

- 搬运了多少有效数据？
- 是否存在重复搬运？
- 指令是否过小、数量是否过多？
- 是否因为布局转换产生额外工作？
- 减少其他管线工作后，总时间是否真的下降？

## 四、从计数器反推代码

当前代码可以解释多项指令计数，这是比“只看百分比”更可靠的训练。

### Cube

每个 N tile 有：

```text
kL1Tiles × l1Prefetch = 28 × 4 = 112 次 Mmad
```

全部：

```text
101 × 112 = 11312
```

与 Cube 指令数完全一致。

### MTE1

每次 inner：

- `SplitA` 执行 1 次 LoadData；
- `SplitB` 在 `baseK/16=4` 次循环中执行 4 次 LoadData。

因此：

```text
SplitA：101 × 28 × 4 = 11312
SplitB：101 × 28 × 4 × 4 = 45248
合计：56560
```

与 `Memory.csv` 的 `aic_mte1_instructions=56560` 完全一致。

### MTE3

- `CopyA` 中 zero UB→A1 的 DataCopy：每个 outer 一次；
- `CopyOut` 中 UB→GM：每个 N tile 一次。

```text
zero 路径：101 × 28 = 2828
输出路径：101
合计：2929
```

与 `aic_mte3_instructions=2929` 完全一致。

### MTE2

主循环中的 GM→L1：

```text
CopyB：101 × 28 × (256/16) × (160/16)
     = 452480 次
CopyA 第 0 行：101 × 28 × (256/16)
             = 45248 次
主循环合计：497728 次
```

硬件报告为 497736 次，存在 8 次差额。不要强行把差额归入某条指令；它可以作为后续通过修改实验、反汇编或工具文档继续研究的问题。

## 五、假设写法模板

一个合格假设必须包含五部分：

```text
观测：哪个指标或代码现象触发思考？
机制：为什么它可能影响总时间？
修改：本次只改变什么？
预测：哪些指标应如何变化？
证伪：出现什么结果就承认假设不成立？
```

### 示例 H1：搬运指令过小

```text
观测：CopyB 主循环约产生 452480 次 MTE2 指令。
机制：每次按 16×16 分形发起搬运，控制和小块传输开销可能限制效率。
修改：重新设计 B 的搬运组织，而不是只改 baseK。
预测：MTE2 指令数下降，总时间或 MTE2 active 下降。
证伪：指令数下降但总时间不变，说明主要限制可能在其他环节。
```

### 示例 H2：双缓冲未充分形成软件流水

```text
观测：A1/B1/A2/B2 申请双缓冲，但当前代码是发起拷贝后较快 DeQue，
      且没有显式提前发起 outer+1 的拷贝。
机制：下一批搬运可能未充分提前，与当前 Mmad 的重叠不足。
修改：只重构预取和队列顺序，保持 tile 大小和数学逻辑不变。
预测：等待指标或总时间改善，MTE2 指令总数基本不变。
证伪：多轮性能无变化或变差，且等待指标没有预期改善。
```

### 示例 H3：N 尾部负载不均

```text
观测：101 个 tile 分给 8 核，5 核执行 13 个，3 核执行 12 个。
机制：完成 12 个 tile 的核可能等待最后 5 个核。
修改：改变 N 任务划分或减少尾部差异。
预测：尾部更均衡时总时间下降。
证伪：均衡后仍无收益，说明尾部不是当前主要限制。
```

## 六、实验设计指导

针对每个假设：

1. 先写下预测，再运行实验；
2. 只改变一个主要因素；
3. 同时记录总时间和机制指标；
4. 保留负结果；
5. 区分“指标改善”和“端到端改善”；
6. 不用当前 310P3 不支持的内部泳道代替证据。

当前设备无法通过 `TimelineDetail` 获取真实 MTE/Cube 内部逐时间泳道，因此本阶段使用：

- 代码静态指令推导；
- 累计管线计数器；
- 单变量实验；
- 应用级 task 时间。

## 七、课后题

### 题 1：为什么管线时间之和大于 aic_time？

这是否说明 profiler 出错？

### 题 2：Cube active 低、Cube wait 高，能否直接得出“增加 Mmad 数量可以提升性能”？

请给出更合理的下一步。

### 题 3：把 Scalar active 减少一半，是否一定节省约 452.8 μs？

为什么？

### 题 4：只改变 baseK，CopyB 的 GM→L1 指令次数会改变吗？

根据 `CopyB` 的循环条件判断。

### 题 5：只改变 l1K，整个算子的 CopyB 指令总数是否必然改变？

假设仍采用相同的 16×16 分形双重循环，且参数合法。

### 题 6：写出一个可被证伪的 Scalar 优化假设。

不能只写“Scalar 很高，所以优化 Scalar”。

### 题 7：101 个 tile 在 8 核上的最大和最小 tile 数分别是多少？

理论尾部差异是多少个 tile？能否据此直接算出总时间损失比例？

### 题 8：为什么不能用 `main_mem_read_bw=1328 GB/s` 直接宣称应用从 DRAM 获得了 1328 GB/s 的有效带宽？

## 八、参考答案

### 答案 1

各管线可以并行和交叠，active 时间统计的不是互斥串行阶段，因此求和没有总时间语义，大于 `aic_time` 并不说明 profiler 出错。

### 答案 2

不能。当前有效计算强度低，MTE2 active 接近满，增加 Mmad 数量通常只会增加计算工作。更合理的下一步是研究上游供数、搬运粒度、依赖等待和 M=1 补零路线，并用单变量实验验证。

### 答案 3

不一定。Scalar 工作可能与其他管线重叠；即使 Scalar 指令减少，如果关键路径仍由 MTE2 决定，总时间可能几乎不变。只有减少关键依赖链上的 Scalar 工作，才更可能转化为端到端收益。

### 答案 4

不会直接改变。`CopyB` 的循环次数由 `l1K/16` 和 `baseN/16` 决定，不使用 `baseK`。`baseK` 会影响 `SplitB`、Mmad 和 L0 Buffer，而不是当前 `CopyB` 的分形循环次数。

### 答案 5

不一定；在相同算法下总数实际上保持不变：

```text
每个 N tile 的 CopyB 次数
= (K/l1K) × (l1K/16) × (baseN/16)
= K × baseN / 256
```

再乘 `N/baseN` 个 N tile：

```text
总次数 = K × N / 256 = 452480
```

`l1K` 会改变每批大小、外层循环和同步组织，但不会改变当前算法下 B 分形搬运指令的理论总数。

### 答案 6

示例：

```text
观测：CopyB 内层反复计算 dstOffset、srcOffset 和分形循环条件，
      Scalar active 为 905.685 μs。
机制：这些运行时地址和循环指令可能与搬运提交竞争 Scalar 资源。
修改：在保持 DataCopy 参数和次数不变的前提下，外提不变量并简化地址递推。
预测：Scalar active 下降，MTE2 指令数不变；若 Scalar 位于关键路径，总时间下降。
证伪：Scalar active 明显下降但总时间不变，或代码变化并未减少 Scalar active。
```

### 答案 7

```text
最大：13 个 tile
最小：12 个 tile
差异：1 个 tile
```

不能直接据此算出总时间损失。是否暴露尾部取决于各核开始时间、每 tile 时间、Device 调度和不同管线重叠，需要实测。

### 答案 8

硬件计数器可能包含多核累计、不同存储层级、重放或特定 PMU 口径，而应用有效带宽应以有效逻辑字节数和同口径时间计算。两者不是同一概念。可以另外计算：

```text
仅 B 的有效读取量 / Device 时间
≈ 231,833,600 / 2.639716 ms
≈ 87.8 GB/s
```

这只是以 B 逻辑读取量估算的有效值，也不等于完整物理 DRAM 流量。
