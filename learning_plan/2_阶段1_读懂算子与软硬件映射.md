## 二、阅读顺序

### 1. 从 Python 入口开始

阅读 `matmul_m1.py:14-48`，确认：

```text
输入 A：[1, 7168]，FP16
输入 B：[7168, 16160]，FP16
输出 C：[1, 16160]，FP16
正式调用：torch_npu.npu_matmul_lyc_custom(a, b)
```

这里虽然名字叫 MatMul，但 M=1，数学上更接近矩阵向量乘 GEMV。B 的每一列与一个商品对应，A 是用户兴趣向量。

### 2. 阅读 Torch 扩展和 Host launcher

重点查看：

- `matmul_lyc_custom/op_host/matmul_lyc_custom_host.cpp:17-37`：查询 Cube 核数、计算 Tiling、启动 kernel；
- `matmul_lyc_custom/op_host/matmul_lyc_custom_tiling.cpp:8-37`：生成标量 Tiling 参数。

## 三、必须掌握的数据通路

```text
GM A ──拷贝第 0 行──┐
                    ├─→ L1 A1 ──LoadData──→ L0A A2 ┐
zero UB ──补零──────┘                              │
                                                   ├─→ Mmad → L0C CO1
GM B ──ND → zZ──────→ L1 B1 ──转置 LoadData→ L0B B2 ┘        │
                                                               ↓
                                              FP32 → FP16，matrix mode
                                                               │
                                                               ↓
                                                         UB cUb │
                                                               ↓
                                        提取每个 16×16 分形的第 0 行
                                                               │
                                                               ↓
                                                             GM C
```

关键点：

- GM 中的 B 是普通 ND `[K,N]`；
- `CopyB` 在 L1 中构造 zZ：K 分形在外、N 分形在内，分形内部为 16×16；
- `SplitB` 使用 `ifTranspose=true`，将 L1 zZ 转为 L0B nZ；
- A 只有第 0 行有效，其余 15 行补零；
- L0C 使用 FP32 保存累加结果；
- 当前 DAV_2002 路径经过 L0C→UB→GM，而不是 L0C→GM Fixpipe。

## 四、Buffer 容量手算指导

当前单核 Buffer 配置如下，单位换算使用 1 KiB=1024 字节：

| Buffer | 计算式 | 单块/总量 | 大小 |
|---|---|---|---:|
| A1 | `2 × 16 × 256 × 2` | 双缓冲总量 | 16 KiB |
| B1 | `2 × 256 × 160 × 2` | 双缓冲总量 | 160 KiB |
| A2 | `2 × 16 × 64 × 2` | 双缓冲总量 | 4 KiB |
| B2 | `2 × 64 × 160 × 2` | 双缓冲总量 | 40 KiB |
| CO1 | `1 × 16 × 160 × 4` | 单块 | 10 KiB |
| cUb | `16 × 160 × 2` | 单块 | 5 KiB |
| zeroUb | `16 × 256 × 2` | 单块 | 8 KiB |

由此得到：

```text
L1 中 A1+B1：176 KiB
UB 中 cUb+zeroUb：13 KiB
```

这些是代码申请的 Buffer，不等同于芯片全部可用容量，也不应把不同存储层级相加后判断某一种容量是否足够。

## 五、理解任务划分和 K 累加

### N 方向

`Process` 使用：

```cpp
for (uint32_t tileIdx = GetBlockIdx(); tileIdx < nTiles_;
     tileIdx += GetBlockNum())
```

8 个核处理 101 个 tile：

```text
5 个核处理 13 个 tile；
3 个核处理 12 个 tile；
5 × 13 + 3 × 12 = 101。
```

### K 方向

每个 N tile：

```text
外层 K/L1 tile：28 次；
每次 L1 tile 内：4 个 baseK；
每核每个 N tile 的 Mmad：28 × 4 = 112 次。
```

只有 `outer==0 && inner==0` 时设置 `cmatrixInitVal=true`，后续 Mmad 继续在同一个 L0C 上累加，直到 K=7168 全部完成。

### 题 2：有效算术强度

只考虑 B 必须至少读取一次，估算有效算术强度，并说明它为什么偏低。

### 题 3：单个 N tile 的 B 数据量

一个 `baseN=160` 的 N tile 完成全部 K 累加，需要读取多少字节的 B？

### 题 4：Mmad 总次数

```text

```

### 题 5：为什么 M=1 还要补零到 16 行？

如果直接将 Mmad 的 `m` 改为 1，是否能自动获得 16 倍加速？为什么？

### 题 6：为什么输出只有 16160 个有效值？

L0C 每个 N tile 有 `16×160` 个 FP32 元素，但最终为什么只写回 160 个 FP16 元素？

### 题 7：全一输入的结果是什么？

如果 A 和 B 的所有元素都为 1，C 的每个元素应该是多少？这个测试能发现哪些问题，又不能发现哪些问题？

### 题 8：Cube 活跃低是否说明 Mmad 没有执行？

已知 Cube 活跃比例约 2.85%，能否据此认为算子没有真正使用 Cube？

## 八、参考答案

### 答案 1

```text
A = 1 × 7168 × 2 = 14,336 字节
B = 7168 × 16160 × 2 = 231,833,600 字节 ≈ 221.1 MiB
C = 1 × 16160 × 2 = 32,320 字节 = 31.5625 KiB

有效 FLOPs = 2 × 1 × 7168 × 16160
           = 231,669,760 FLOPs
```

这里的 FLOPs 是数学上的有效计算量，不等于补零后硬件实际执行的 Mmad 运算量。

### 答案 2

```text
有效算术强度 ≈ 231,669,760 / 231,833,600
             ≈ 0.9993 FLOP/Byte
```

约为 1 FLOP/Byte。每读取一个 FP16 B 元素，只对应一次有效乘法和一次有效加法，因此数据量很大而有效计算密度低，应优先检查内存和搬运路径。

### 答案 3

```text
7168 × 160 × 2 = 2,293,760 字节
               = 2240 KiB
               ≈ 2.1875 MiB
```

### 答案 4

```text
每个 N tile：28 × 4 = 112 次 Mmad
全部 N tile：101 × 112 = 11,312 次 Mmad
```

与 Cube 指令计数完全一致。这说明可以用代码静态推导校验硬件计数器，而不是只看利用率百分比。

### 答案 5

当前 Mmad 数据通路按 16 行分形组织，A 和 L0C 都按 `FRACTAL_M=16` 分配。补零使普通 Mmad 能处理这个 GEMV，同时保证其余行不影响第 0 行。

不能据此认为把 `m` 改成 1 就能获得 16 倍加速。Buffer 布局、LoadData、Mmad 参数和输出路径都围绕 16 行分形设计，而且当前主要瓶颈表现为 MTE2，而不是 Cube 乘加吞吐。

### 答案 6

A 的第 1～15 行全是零，因此对应输出行没有业务意义。每个 16×16 输出分形只需保留第 0 行；10 个 N 分形各保留 16 个值，合计 `10×16=160` 个 FP16 输出。

### 答案 7

每个输出为：

```text
C[n] = Σ A[k] × B[k,n] = 7168
```

该测试容易发现漏累加、K 循环次数错误、部分 tile 未计算和明显布局错误。但它对索引置换、部分位置错误和特殊数值问题不敏感，例如某些错误交换可能仍得到相同结果。因此还需要随机输入、多 seed 和参考 MatMul 对比。

### 答案 8

不能。11,312 次 Cube 指令和 74.627777 μs Cube 活跃时间证明 Mmad 确实执行。活跃比例低表示在整段任务时间内 Cube 活跃窗口占比较小，不表示指令不存在；还可能同时存在 Cube 等待数据的情况。
