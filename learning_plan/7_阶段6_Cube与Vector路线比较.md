# 阶段 6 指导：比较 Cube 与 Vector 的 GEMV 技术路线

> 对应总计划的阶段 6  
> 建议用时：1～2 周  
> 前置要求：已经完成基线、profiling、Tiling 和至少一项代码结构实验。  
> 本阶段原则：先设计公平实验，再实现新路线；不以“必须跑赢 Cube”为唯一目标。

## 一、学习目标

完成本阶段后，你应能：

1. 从 shape 和算术强度选择候选硬件路线；
2. 解释 M=1 补齐到 16 行的收益和代价；
3. 设计 FP32 累加语义可比的 Vector GEMV；
4. 区分计算单元效率与内存系统瓶颈；
5. 完成一份有证据、有负结果的算子优化报告。

## 二、为什么需要重新审视 Cube 路线

当前 Cube 实现的优势：

- 已有正确、可复现的完整数据通路；
- 利用 Mmad 和 FP32 L0C 累加；
- Mmad 次数与硬件计数器可以精确对应；
- 对后续扩展到较大 M 有学习价值。

当前局限：

- 有效 A 只有 1 行，但 Mmad 按 16 行分形执行；
- A1、L0C 和输出中间布局都围绕 16 行组织；
- 有效算术强度约为 1 FLOP/Byte；
- MTE2 active 约 99.15%，Cube active 约 2.85%；
- B 的搬运和布局组织是主要研究对象。

因此可以提出：

> 对 M=1，Vector 乘加与归约是否比补零 Mmad 更自然？即使更自然，它能否突破相同的数据搬运限制？

## 三、先推导，不急于写 Vector kernel

### 1. 有效计算强度

对一般 M，在忽略 A/C、B 只读一次时：

```text
有效 FLOPs = 2 × M × K × N
B 字节数   = K × N × 2
有效强度   ≈ M FLOP/Byte
```

所以：

```text
M=1：约 1 FLOP/Byte
M=16：约 16 FLOP/Byte
```

M 增大时，B 可以被更多行复用，Cube 路线通常更有吸引力；M=1 时则必须首先审视数据移动。

### 2. 补零带来的硬件工作

当前 Mmad 的 M 固定为 16，而有效结果只有第 0 行。因此从数学角度看，16 行 Mmad 路径存在大量无业务意义的行计算。

但“无效计算多”不自动等于“总时间慢 16 倍”：Cube active 本来就很低，主要时间可能由搬运决定。优化无效计算若不影响关键路径，收益可能很小。

## 四、Vector GEMV 的概念设计

一种概念方案是按 N 方向组织向量累加：

```text
对一个 N tile：
  acc[0:baseN] = 0，使用 FP32

  对 k = 0 ... K-1：
    读取 A[k]
    读取 B[k, nOffset:nOffset+baseN]
    acc += broadcast(A[k]) × B[k, 当前 N 区间]

  将 acc 转为 FP16 并输出
```

实际 AscendC 实现还需要解决：

- GM→UB 或其他存储路径；
- FP16 输入到 FP32 累加的转换；
- A 标量广播和 Vector 指令形式；
- K 循环与向量长度；
- 多核 N 任务分配；
- 累加顺序和数值误差；
- 输出对齐和尾部；
- 队列、同步与双缓冲。

这段伪代码只用于算法规格设计，不应直接当作可编译 AscendC 代码。

## 五、公平比较规则

Vector 与 Cube 版本必须保持：

| 项目 | 公平要求 |
|---|---|
| 输入 | 相同 A/B、shape、dtype 和 ND 格式契约 |
| 输出 | 相同 shape、dtype 和数值语义 |
| 累加 | 都明确 FP32 累加，不能一个 FP32、另一个低精度后直接比较性能 |
| Device | 同一 NPU、相近环境和频率状态 |
| 计时 | 同样的预热、同步和正式三次口径 |
| profiling | 相同指标和 replay 方式 |
| 预处理 | 任何预打包都单独说明成本与复用条件 |
| 精度 | 多 seed、全一、定向输入，并设置合理容差 |

如果 Vector 版本需要不同的 B 布局，必须把格式转换纳入设计说明。不能把已经离线转换好的 B 与需要现场处理 ND B 的 Cube 版本直接比较，然后宣称同契约加速。

## 六、建议的实验顺序

### V0：只做算法与容量设计

不写 kernel，先完成：

- 数据流图；
- UB/L1 等 Buffer 预算；
- 每核任务划分；
- FP32 累加方案；
- 理论搬运量；
- 预期指令和主要风险。

### V1：正确性原型

目标是跑通，不追求最优：

- 小范围定向输入先验证；
- 再验证完整 shape；
- 明确输出与参考 MatMul 的误差；
- 检查是否所有 N 和 K 都被覆盖。

### V2：同口径性能比较

记录：

```text
Device task 时间
MTE2 active 和指令数
Scalar active
Vector/Cube active
Vector/Cube wait
精度与波动
```

当前 310P3 无法获取真实 MTE/Cube 内部逐时间泳道，因此不能用累计统计拼造 Timeline。

### V3：只优化更快路线的主要限制

- 如果两者 MTE2 都接近满且总时间接近，优先研究共同搬运路径；
- 如果 Vector 的 Scalar 很高，先研究 K 循环和地址控制；
- 如果 Cube 版本 Cube wait 高但总时间不变，继续查供数与关键路径；
- 如果一条路线明显更差，保留负结果并解释，不必无限投入。

## 七、建立简单的带宽下界分析

只考虑 B 至少读取一次：

```text
最小逻辑 B 流量 = 231,833,600 字节
```

基线正式 Device 平均为 2639.716 μs，因此以 B 逻辑量估算：

```text
有效 B 读取速率 ≈ 231,833,600 / 0.002639716
                ≈ 87.8 GB/s
```

这个值不是硬件峰值，也不是完整物理 DRAM 带宽。要建立更可信的下界，应在相同 Device 上设计与 B 大小和访问方式相近的独立拷贝/读取基准，测量可持续有效带宽，再估算：

```text
理想搬运下界 ≈ 必要逻辑字节数 / 同口径可持续有效带宽
```

注意：

- 独立基准只能提供参照，不保证 GEMV 一定能达到；
- L2/缓存、重复运行和数据驻留可能影响结果；
- 不应把 `Memory.csv` 的多核/硬件层级计数直接当成应用有效 DRAM 带宽；
- 若已接近可信下界，继续调 Cube 参数的空间可能有限。

## 十、参考答案

### 答案 1

B 被更多 A 行复用，同样读取一次 B 可以完成更多有效计算。近似算术强度从 `M=1` 时的约 1 FLOP/Byte 增长到 `M=16` 时的约 16 FLOP/Byte，Cube 的高吞吐更可能被利用，16 行分形也不再主要被零行占据。

### 答案 2

不一定，且当前数据不支持这种推断。16 倍只是行数上的直观比例，不是总时间预测。当前 Cube active 低、MTE2 active 接近满，如果两个版本都读取同样的 B 并受同一搬运路径限制，减少无效 Cube 工作可能只带来很小收益。

### 答案 3

当前基线采用 FP32 L0C 累加，Vector 版本使用 FP32 才能保持相近数值语义并进行公平比较。FP16 累加会改变舍入、溢出风险和累加误差，也可能改变指令成本；此时速度和精度差异同时变化，无法只归因于执行单元路线。

### 答案 4

优先研究两个版本共享的数据搬运和布局路径，例如 B 的访问组织、搬运粒度、重复流量和指令组织，而不是继续单纯增加 Vector/Cube 计算指令。还应建立同口径有效带宽参照，判断是否接近实际限制。

### 答案 5

87.8 GB/s 是用“B 的逻辑字节数 ÷ 某次 Device 平均时间”得到的应用有效值。它没有包含全部物理流量，也不是硬件规格峰值；硬件 PMU 还可能采用多核累计和不同存储层级口径。三者必须分开。

### 答案 6

最适合 B 是可复用权重、初始化后执行多次推理的场景。报告应分别给出初始化/预打包成本、稳态 kernel 时间、复用次数或摊销假设，并明确自定义算子的输入格式契约已经改变。对于每次变化的 B，应把转换成本计入端到端。

### 答案 7

先定义应用可接受的数值误差和参考累加口径，检查是否由累加顺序、FP16 中间累加或转换引起。不能只报告速度。如果误差超出要求，该版本不能替代基线；如果在明确容差内，也应同时报告 max/mean 误差、速度和测试分布。

### 答案 8

不说明失败。若你完成了可信基线、单变量实验、负结果归因、带宽下界和路线比较，并能证明为什么当前实现难以继续提升，就已经达到核心学习目标。凭空获得一个没有证据的 10% 数字，反而不如可靠的性能边界分析。

## 十一、结课验收标准

建议按以下维度自评，每项 0～2 分：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 正确性 | 结果不可靠 | 基本通过 | 多 seed、定向输入和边界均通过 |
| 测量 | 混用口径 | 基线可运行 | 同口径、可复现、有波动分析 |
| 瓶颈分析 | 只看百分比 | 能联系代码 | 有指令账本和可证伪假设 |
| 实验设计 | 多变量乱改 | 有部分单变量 | 完整单变量矩阵和负结果 |
| 优化效果 | 无有效数据 | 有局部改善 | 有复测的端到端结果或可信边界证明 |
| 总结迁移 | 只给最优参数 | 有报告 | 能解释 shape、布局和路线适用边界 |

达到 10～12 分，说明已经掌握本项目预期的核心分析与优化方法。

> 最终目标不是背下一组 Tiling 参数，而是能够独立重复：  
> **测量 → 假设 → 实验 → 验证 → 归因 → 总结边界。**
